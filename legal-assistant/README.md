# Юридический ассистент (Hack&Change 2026, кейс ПСБ)

ИИ-ассистент для юристов: отвечает на вопросы **только по предоставленной базе нормативных документов**, указывает конкретные пункты и статьи, обоснованно отказывает, если данных недостаточно, исправляет ошибочные предпосылки, учитывает редакции документов на дату события и устойчив к prompt injection.

## Быстрый запуск (Docker)

```bash
cp .env.example .env    # впишите LLM_BASE_URL и LLM_API_KEY
docker compose up --build
```

Откройте http://localhost:8000. Порт меняется переменной `PORT`.

Без Docker: `pip install -r requirements.txt`, затем `uvicorn server:app --port 8000`.

## Архитектура

```
вопрос / диалог
   │  parse_dialog: «Пользователь: … Ассистент: …» → реплики
   ▼
Гибридный поиск (legal_rag/search.py)
   ├─ BM25 по фрагментам (русский стемминг, синонимы «аванс ↔ предоплата» и т. п.)
   ├─ плотный поиск bge-m3 (эмбеддинги кэшируются в cache/embeddings.json)
   ├─ слияние RRF + бонус за номер договора в вопросе
   └─ реранкер (опционально; при ошибке автоматически отключается)
   ▼
Сборка контекста на уровне документов
   ├─ небольшие документы — целиком (договор, регламент, письмо)
   ├─ большие статьи законов — только найденные пункты с локаторами «п. 3, подп. 2.1»
   └─ связанные документы: все редакции регламента, доп. соглашения к договору
   ▼
Генерация (DeepSeek V4.1 Flash): системный промпт с правилами достоверности
   + перечень ВСЕХ документов базы (модель видит границы знаний)
   → <analysis> скрытый разбор → <answer> ответ → <sources> ссылки на положения
   ▼
Самопроверка (VERIFY=true): отдельный вызов сверяет цифры, пункты, редакцию,
   обоснованность отказа и при необходимости исправляет ответ
   ▼
Ответ + подтверждающие фрагменты (UI подсвечивает пункт в тексте документа)
```

### Контроль достоверности

| Ситуация | Как обрабатывается |
|---|---|
| Нет данных в базе | Перечень документов базы в промпте; правило «назови, чего не хватает, не отвечай по памяти»; самопроверка проверяет, что отказ обоснован |
| Ошибочная предпосылка | Правило исправления со ссылкой; проверка на этапе верификации |
| Дата и редакция | Все редакции документа попадают в контекст вместе со статусом «утратила силу»; доп. соглашения подтягиваются по номеру договора; для законов — сообщение об отсутствии прежней редакции |
| Противоправные запросы | Отказ с разъяснением требований и последствий по документам базы |
| Смена роли / поддельные системные сообщения | Вопрос передаётся как данные в обёртке; правила роли в системном промпте; давление пользователя не меняет подтверждённый ответ |
| Инструкции внутри документов | Строки, адресованные ИИ, вырезаются при индексации (`kb.clean_text`) и дополнительно запрещены промптом |
| Непрофильные вопросы | Вежливое объяснение границ компетенции |

## Структура

```
legal_rag/
  config.py      переменные окружения
  kb.py          загрузка (txt/md/docx, zip или папка), очистка, разбиение по пунктам
  search.py      BM25 + эмбеддинги + RRF + реранкер, сборка контекста
  llm.py         клиент OpenAI-совместимого API (chat, embeddings, rerank), ретраи
  assistant.py   промпты, разбор диалога, генерация, самопроверка, источники
  runtime.py     сборка ассистента
solution.py      точка входа для платформы (questions.csv → submission.csv)
server.py        FastAPI: /api/chat, /api/documents, /api/health
static/          веб-интерфейс чата с просмотром документов
tools/make_submission.py   сборка dist/submission.zip для платформы
tools/evaluate.py          прогон демо-вопросов и оценка LLM-судьёй → eval_report.md
data/knowledge-base/       база знаний
```

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `LLM_BASE_URL` | адрес OpenAI-совместимого API | — |
| `LLM_API_KEY` | ключ API | — |
| `LLM_MODEL` | генеративная модель | `deepseek/deepseek-v4.1-flash` |
| `EMB_MODEL`, `EMBEDDER_API_KEY` | эмбеддер | `baai/bge-m3`, ключ LLM |
| `RERANKER_MODEL`, `RERANKER_API_KEY`, `USE_RERANKER` | реранкер | `cohere/rerank-5-fast`, ключ LLM, `true` |
| `VERIFY` | этап самопроверки ответа | `true` |
| `TOP_CHUNKS` | число фрагментов после поиска | `10` |
| `SMALL_DOC_CHARS` | документы короче — в контекст целиком | `9000` |
| `MAX_WORKERS` | параллельная обработка вопросов | `4` |
| `DATA_DIR`, `KB_DIR` | где искать `questions.csv` и базу | `data` |
| `PORT` | порт веб-интерфейса | `8000` |

## Сабмит на платформу

```bash
python tools/make_submission.py   # → dist/submission.zip
```

Архив содержит `solution.py`, пакет `legal_rag`, кэш эмбеддингов и `requirements.txt` (`httpx`). Платформа сама передаёт `LLM_BASE_URL`, ключи и `data/questions.csv`, `data/kb.zip`.

Локальный прогон так же, как на платформе:

```bash
python solution.py          # data/questions.csv → submission.csv
python tools/evaluate.py    # сравнение с data/demo_output.csv → eval_report.md
```

## Проверка основного сценария

1. Откройте интерфейс, нажмите пример «Договор на 12 млн рублей заключали в августе 2024 года…».
2. Ответ должен опираться на редакцию регламента 2023 г. (п. 2.4) и пояснить, что новая редакция к договору не применяется.
3. Нажмите на чип источника — справа откроется документ с подсвеченным пунктом.
4. Спросите «Какой размер пособия по беременности и родам?» — ассистент сообщит, что таких документов в базе нет.

## Известные ограничения

- Законы в базе представлены отдельными статьями в действующей редакции; связанные статьи (например, ст. 6 152-ФЗ) недоступны — ассистент сообщает об этом.
- Стемминг упрощённый (без морфологического словаря); полнота поиска обеспечивается эмбеддингами.
- Самопроверка удваивает число вызовов LLM; для ускорения можно установить `VERIFY=false`.
- Персональные данные в базе — вымышленные.
